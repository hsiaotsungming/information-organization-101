Graph RAG 與 LLM

Graph RAG 把 RAG 的檢索流程和知識圖譜中的實體關係結合起來，讓系統不只找相關文字，也能沿著資料中的關係脈絡來回答問題。

本單元目標

  • 區分一般 RAG 與 Graph RAG 在檢索概念上的差別。
  • 理解 Graph RAG 如何根據實體與關係進行檢索。
  • 說明知識圖譜中的資料可以從哪些來源而來，並理解它如何成為 Graph RAG 的知識基礎。

RAG 與 Graph RAG

RAG 與 Graph RAG 進行檢索時，操作概念有明顯的不同。在 RAG 中，檢索通常是從一組文件、段落或資料庫紀錄中，找出和使用者問題在語意上接近的文字片段。檢索通常是從一組文件、段落或資料庫紀錄中，找出和使用者問題在語意或關鍵字上相近的文字片段。文件與問題都會先被轉換成向量，才能進行語意上的比對。大型語言模型接著根據這些被找回來的文字，整理並生成回答。

Graph RAG 則是通常以知識圖譜為基礎，檢索實體、關係與屬性所形成的結構。它不只判斷文字與問題間的相似度，也會辨識這些實體間的關係或結構能否回應問題。因此，Graph RAG 的檢索單位會是有著像人物、地點、作品、機構、事件、主題詞等實體，以及這些實體的屬性和實體間的關係。

兩者的差異可以概括為，RAG 的檢索核心是語意相似的文本片段，Graph RAG 的檢索核心則是文本背後的實體、關係、屬性所構成的結構脈絡。前者適合回答局部、明確、文本證據集中於少數段落的問題。後者則更適合處理需要跨越多個實體、順著關係脈絡推理的問題，兩者在實務上也常搭配使用。

比方說，讀者提出「哪些人曾同時研究清代文字獄與出版審查，且其著作被收錄於同一機構館藏」這個問題。若用傳統檢索，讀者得分別查詢兩個主題、人工比對學者名單，再逐一確認各館館藏。RAG 雖能找到語意相近的段落，卻難以將散落各處的學者、著作與館藏串連起來。Graph RAG 則能沿著主題、學者、著作、館藏機構之間的關係脈絡逐步推導，一次找到答案。

簡言之，RAG 是把問題帶到文本集合中尋找相關內容。Graph RAG 則是先把文本集合轉換成可檢索、可摘要、可局部放大也可全域俯瞰的知識結構，再根據這個結構生成回答。這也是 Graph RAG 與 RAG 在檢索概念上最根本的差異。

進行實體關係檢索

Graph RAG 的關鍵，是讓系統能夠沿著實體之間的關係進行檢索。這裡的「沿著關係」可以理解為：系統不是只比對一段文字是否相似，而是從某個實體出發，依照資料中定義好的關係，找到其他相關實體。

例如，在圖書館資料中，「某作者—創作—某作品」、「某作品—具有主題—民俗信仰」、「某作品—有版本—繁體中文譯本」、「某版本—館藏於—某分館」都可以被視為實體關係。當使用者提出自然語言問題時，系統可以先辨識問題中的條件，再轉換成圖譜中的查詢路徑。這個過程不只是找出含有關鍵字的紀錄，而是判斷哪些資料在結構上符合使用者的需求。

知識圖譜常見的查詢語言包括 SPARQL 與 Cypher。SPARQL 是 RDF 知識圖譜常用的查詢語言，適合針對「主詞—謂詞—受詞」形式的資料進行語意精確的查詢；Cypher 則常見於 property graph 的查詢環境，使用圖形化的節點與關係模式描述查詢。這些查詢語言提供了一種方式，讓系統可以精確地表達「我要找哪些實體，以及它們之間必須具有什麼關係」。

Graph RAG 的優勢

Graph RAG 適合處理需要理解資料之間關係的問題。如果只是問一段文件的摘要、某個條文的內容，或某份報告中的明確資訊，一般 RAG 已經可以處理。但如果問題涉及多個條件、多個實體，或需要跨資料來源整合，Graph RAG 通常更有優勢。這類問題像是：

  • 找出某個主題中，某些作者的作品是否有繁體中文譯本。
  • 推薦與某本書在出版時間、主題上相似，而且目前館內可借的資料。
  • 說明某個人物與事件、地點或作品之間的關係。

這些問題表面上像是自然語言問答，但背後其實需要系統理解不同實體之間的關係。

Graph RAG 也適合用在資料來源彼此相連的情境。知識圖譜的一個優點是可以和文字資料、不同資料集或外部知識來源結合。例如，可以把文字中的實體辨識出來，並連結到知識圖譜中的實體；也可以透過不同資料集之間的實體連結，進行跨來源查詢。由於是基於抽取出來的實體關係，Graph RAG 在需要基於事實資料回答的應用上，會更具優勢。

但由另一方面來說，當資料本身沒有被整理成實體與關係，或者關係不清楚，Graph RAG 的效果就會受到限制。它不是讓模型變得自動理解所有關係，而是依賴資料中已經存在、或可以被抽取與建構出來的關係。因此，越是需要根據明確關係回答的問題，越適合使用 Graph RAG；越是單純摘要文字或回答單一文件內容的問題，則不一定需要加入圖譜。

知識圖譜的角色

知識圖譜讓原本分散在不同欄位、紀錄或文件中的資訊，組織成可以被查詢與推理的關係網絡，成為 Graph RAG 的知識基礎。大型語言模型負責生成自然語言回答，而知識圖譜提供回答的依據，協助系統判斷哪些實體相關、它們如何連接，以及哪些資料可以作為回答依據。

知識圖譜的基本資料模型雖然簡單，但相當有彈性。節點代表實體，帶標籤的邊代表關係，而 RDF 則以主詞、謂詞、受詞三元組作為核心資料模型。這種形式使得知識圖譜能夠描述人物、作品、地點、事件、主題、分類與其他實體之間的連結。這可以將原有資訊組織的結果，轉成使用 RDF 表示。也能在 LLM 或其它電腦工具的協助下，從非結構化資料中，抽取主詞、謂詞、受詞來形成 RDF 關係。

在圖書館場景中，知識圖譜可以來自既有的資訊組織成果，例如書目紀錄、權威控制、主題標目、分類號、館藏資料、數位典藏詮釋資料與外部識別碼。這些資料若只是被當成文字欄位使用，模型只能做相似度比對，但若被整理成圖譜，系統就可以更清楚地知道這是不是同一位作者、這是不是同一作品的不同譯本、這個主題是不是另一個主題的下位概念等。

在 LLM 的應用場景中，RDF 可以來自大量非結構化資料，例如研究論文、新聞報導、網頁內容、館藏描述、訪談紀錄、使用者評論與數位典藏文本。這些資料若只是被當成一般文字處理，模型通常只能依靠語意相似度或關鍵字來理解內容。在透過 LLM 抽取其中的實體、關係與屬性後，就能轉成 RDF 並形成知識圖譜，此時系統就能更明確地分析這些非結構化中的重要實體和關聯。如此一來，原本分散在文本中的知識便能被整理為可查詢、可連結、可推理的結構化資料。

小練習

  1. 用自己的話說明 Graph RAG 和一般 RAG 最大的不同是什麼。
  2. 請說明知識圖譜中的資料可以從哪些來源而來，並舉出一到兩種可能的資料形式。
  3. 請說明如果知識圖譜中的實體關係整理得不清楚或連結錯誤，Graph RAG 可能會受到哪些影響。
